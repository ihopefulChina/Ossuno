# Ossuno 1.0.2

这是一次稳定性更新，修复搜索检查器、上传路径模板、传输暂停/继续，以及 `ossuno-mcp` 的安装配置与本地路径策略。

## 下载 Ossuno 1.0.2

- [Apple Silicon 版（M 系列芯片）](https://github.com/ihopefulChina/Ossuno/releases/latest/download/Ossuno-1.0.2-arm64.dmg)
- [Intel 版（x86_64）](https://github.com/ihopefulChina/Ossuno/releases/latest/download/Ossuno-1.0.2-x86_64.dmg)

两个安装包都需要 macOS 15 或更高版本。不确定芯片类型时，可在苹果菜单的「关于本机」中查看“芯片”或“处理器”。

## 修复

- Bucket 搜索和大文件筛选里打开「信息」现在显示所选搜索结果，而不是背后隐藏的文件夹列表；下载和删除按钮与标题一致。搜索结果刷新后，删除确认仍会列出待删文件名。
- 账号路径模板若包含 `{filename}` 或 `{name}`，上传不再把文件名再拼一层（例如 `assets/hero.png/hero.png`）。
- 暂停正在传输的任务后再继续，不会叠跑两次上传/下载；转换 HEIC 或等待 iCloud 下载时取消，会按暂停/取消处理，而不是记成失败。
- 无法读取的文件夹上传会明确失败，而不是静默跳过。把同名文件和同名文件夹一起拖到访达时，会像访达一样自动编号，避免本地路径冲突。
- 重新运行 `ossuno-mcp install` 会保留已有的 `env`（默认 Bucket、允许目录等），也不会因为 TOML 表头带注释而截断后面的配置。
- MCP 默认允许本机系统临时目录（不只是 `/tmp`）；上传会拒绝硬链接，避免从允许目录里读到目录外的文件。
- 官网顶部「下载」会在识别芯片后改成 Apple Silicon / Intel 文案，避免未标注却始终指向 arm64 安装包。

## 系统要求

- Apple Silicon 或 Intel Mac
- macOS 15 或更高版本

## 分发方式与首次打开

两个 DMG 均采用 ad-hoc 代码签名（没有开发者身份），不是 Developer ID 签名，且未经 Apple 公证。因此 macOS 无法验证开发者或确认安装包已经过 Apple 恶意软件检查，首次打开通常会触发 Gatekeeper。

1. 打开 DMG，把 Ossuno 拖进「应用程序」，然后双击 Ossuno 尝试打开一次。
2. 若 macOS 阻止运行，打开「系统设置 → 隐私与安全」，滚动到“安全性”，点击「仍要打开」。
3. 在再次出现的警告中点击「打开」；系统可能要求密码或 Touch ID。以后可正常双击打开。

仅在确认安装包来自本仓库的 GitHub Releases 时放行。详细背景见 [Apple 的安全打开说明](https://support.apple.com/zh-cn/102445)。
