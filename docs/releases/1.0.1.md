# Ossuno 1.0.1

这是一次稳定性更新，重点修复 Bucket 搜索（含大文件筛选）的选择、菜单、检查器和传输行为。

## 下载 Ossuno 1.0.1

- [Apple Silicon 版（M 系列芯片）](https://github.com/ihopefulChina/Ossuno/releases/latest/download/Ossuno-1.0.1-arm64.dmg)
- [Intel 版（x86_64）](https://github.com/ihopefulChina/Ossuno/releases/latest/download/Ossuno-1.0.1-x86_64.dmg)

两个安装包都需要 macOS 15 或更高版本。不确定芯片类型时，可在苹果菜单的「关于本机」中查看“芯片”或“处理器”。

## 修复

- Bucket 搜索和大文件筛选的右键菜单、键盘快捷键、检查器和下载现在作用于搜索结果，而不是背后隐藏的文件夹列表。
- 从搜索结果下载时保留对象完整路径，避免不同目录下的同名文件互相覆盖。
- 已确认的搜索删除会继续执行，即使结果列表在确认后被刷新清空。
- 搜索里重命名如果打不开所在文件夹，会给出明确提示，而不再静默失败。
- 不再把 Pages、Keynote 等 Mac 程序包展开成内部文件上传；这类项目会明确失败。
- 签名请求拒绝跟随 HTTP 重定向，避免把 `Authorization` 转到其他主机。
- 列举对象时保留 Key、Prefix 和 continuation token 的首尾空格；分片完成 XML 会转义 ETag。
- 未完成的 Bucket 扫描不再写入缓存，避免下次相同查询读到残缺结果。
- 复制到剪贴板后，若系统剪贴板被其他内容替换，云端粘贴会失效，避免贴出过期内容。
- `ossuno-mcp` 同步修正了本地文件大小读取（不再把体积读成 0），并同样保留对象键空白。

## 系统要求

- Apple Silicon 或 Intel Mac
- macOS 15 或更高版本

## 分发方式与首次打开

两个 DMG 均采用 ad-hoc 代码签名（没有开发者身份），不是 Developer ID 签名，且未经 Apple 公证。因此 macOS 无法验证开发者或确认安装包已经过 Apple 恶意软件检查，首次打开通常会触发 Gatekeeper。

1. 打开 DMG，把 Ossuno 拖进「应用程序」，然后双击 Ossuno 尝试打开一次。
2. 若 macOS 阻止运行，打开「系统设置 → 隐私与安全」，滚动到“安全性”，点击「仍要打开」。
3. 在再次出现的警告中点击「打开」；系统可能要求密码或 Touch ID。以后可正常双击打开。

仅在确认安装包来自本仓库的 GitHub Releases 时放行。详细背景见 [Apple 的安全打开说明](https://support.apple.com/zh-cn/102445)。
