首次打开被 macOS 拦截

Ossuno 1.0.5 的 Apple Silicon 与 Intel 两个 DMG 均采用 ad-hoc 代码签名（没有开发者身份），不是 Developer ID 签名，且未经 Apple 公证。因此 macOS 无法验证开发者或确认安装包已经过 Apple 恶意软件检查，首次打开通常会触发 Gatekeeper。

  1. 打开 DMG，把 Ossuno 拖进「应用程序」，然后双击 Ossuno 尝试打开一次。
  2. 若 macOS 阻止运行，打开「系统设置 → 隐私与安全」，滚动到“安全性”，点击「仍要打开」。
  3. 在再次出现的警告中点击「打开」；系统可能要求密码或 Touch ID。以后可正常双击打开。

仅在确认安装包来自 Ossuno 的 GitHub Releases 时放行。Apple 也提醒，绕过这项保护会承担没有已验证开发者身份、未经公证软件的安全风险；可先阅读 Apple 的安全打开说明。

无法连接账号

  1. 确认使用 RAM 子用户，而不是主账号 AccessKey；从仅允许访问所需 Bucket 的最小权限开始。
  2. 检查 AccessKey ID、Secret、可选 STS Token 与地域是否匹配。临时 Token 过期后需要重新填写。
  3. 使用自定义 Endpoint 时填写完整主机名；私有网络地址只有在当前 Mac 能访问对应网络时才可用。
  4. 如错误包含权限拒绝，请在阿里云控制台核对列举、读取、上传、删除或复制操作所需的 RAM 权限。安全复制与回滚还会按场景使用 oss:GetBucketVersioning、oss:GetObjectAcl、oss:GetObjectVersion 和 oss:DeleteObjectVersion。

上传或下载失败

短暂断网、限流和 OSS 服务端故障会自动重试。大文件上传与下载会保存检查点；在传输中心暂停后，可从已经完成的分片或字节范围继续。

下载不会覆盖本地同名文件。若继续或重试不可用，请查看任务说明；常见情况是原文件已移动、云端对象已变化，或 macOS 不再允许访问之前选择的目录。

删除后能否恢复

Bucket 开启版本控制时，刚删除的项目可以立即按 Command–Z 撤销。未开启版本控制时，删除是永久的。

跨 Bucket 操作为什么会经过这台 Mac

同一账号、同一地域的 Bucket 使用 OSS 云端复制。跨地域或跨账号时，Ossuno 会在确认页明确显示“通过这台 Mac 中转”，先下载到受控临时目录并校验，再上传到目标。安全覆盖要求目标 Bucket 已开启版本控制；未开启时请选择“保留两者”或跳过。移动仅在全部目标复制完成、来源与目标 Bucket 都开启版本控制且能按精确版本验证时清理来源；其他状态会安全取消，请改用复制后手动核对。

账号配置异常

Ossuno 会保留上一份可读取的账号配置。主配置损坏时会尝试自动恢复并保留损坏文件；如果备份也不可读，请先不要覆盖本地应用数据，然后复制诊断信息并提交 Issue。

更新或 1.0.5 迁移

从 1.0.4 或更早版本升级到 1.0.5 必须手动安装。1.0.5 将 Bundle ID 从 studio.ossuno.oss 更正为 app.ihopeful.Ossuno，Sparkle 无法以新身份直接替换旧应用；旧版“检查更新”只会显示迁移说明并引导下载。

  1. 退出正在运行的旧版 Ossuno。
  2. 从下载区或发布页下载与 Mac 芯片匹配的 1.0.5 DMG，将 Ossuno 拖入「应用程序」并确认替换。
  3. 首次启动 1.0.5 后，旧偏好与账号显示配置会迁移，并继续查找原服务名下的钥匙串凭证。由于应用身份已变更，macOS 可能要求你允许访问；允许后无需重新输入。系统也可能再次请求通知权限。

完成迁移后，后续同一 Bundle ID 的版本可继续在“Ossuno → 检查更新…”中安装。自动检查可在“设置 → 通用”中开启；网络代理或无法访问 GitHub Releases 时，请手动下载。

让 AI 操作 OSS（MCP）

ossuno-mcp 已发布到 npm。运行 npx ossuno-mcp auth 配置凭证，再运行 npx ossuno-mcp install，即可注册到 Codex、Claude Desktop、Claude Code、Cursor、Trae、Windsurf 等本机 AI 客户端。AI 可浏览 Bucket、上传下载文件和生成临时下载链接，并自带 OSS 专家提示词；凭证保存在 macOS 钥匙串，与 App 账号相互独立。查看 ossuno-mcp 接入指南，完整命令与客户端配置见 GitHub 文档。

提交可复现的问题

在 Ossuno 中选择“帮助 → 复制诊断信息”，然后创建结构化 Issue。附上最小复现步骤、实际结果与期望结果。

截图和录屏请使用虚拟数据，或遮盖账号、Bucket、对象名、路径与 URL。不要提交 AccessKey、Secret、Token 或签名 URL。安全漏洞应使用私密报告。
